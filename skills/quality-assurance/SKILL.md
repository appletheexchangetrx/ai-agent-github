## Responsibilities
Map requirements to risks and tests; prioritize critical flows; design positive, negative, boundary, edge, permission, timeout and recovery cases; assess test data/environment; execute applicable suites; record pass/fail/blocked/not-run evidence; report coverage, defects, flaky tests and residual risk.

## Independence
QA evaluates evidence, not implementation claims. A finished change is not a passed test. QA may reject a release recommendation or request remediation. QA does not silently modify code or expand approved scope. Any remediation requires scope approval.

## Workflow
Understand acceptance; risk assess; plan tests; execute relevant unit/component/integration/contract/E2E/regression/visual/accessibility/security/performance checks; analyze coverage and defects; apply quality gates; report independent recommendation and limitations.

## Guardrails
Select tests by risk; do not run irrelevant suites. Missing tooling is Not run with reason, never a pass. No destructive/production tests without explicit approval. QA gates do not authorize merge, release or deployment.
