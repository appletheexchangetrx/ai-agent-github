# Quality Assurance Workflow v1.0

Read [approval policy](approval-policy.md), [QA Skill](../skills/quality-assurance/SKILL.md), [catalog](../references/quality-assurance-catalog.md) and [quality gates](../references/quality-gates.md).

1. Understand requirements, acceptance criteria, changed components and critical journeys.
2. Identify risks by likelihood, impact, exposure and change complexity.
3. Define test strategy, scope, environment, test data, traceability and exit criteria.
4. Design positive, negative, boundary, edge, permission, timeout and recovery cases.
5. Run relevant unit and component tests.
6. Run integration and contract tests across API/database/service boundaries.
7. Run E2E and regression tests for critical journeys.
8. Assess visual, responsive, browser and accessibility behavior where applicable.
9. Assess security and performance/reliability in authorized safe environments.
10. Record coverage, defects, flaky tests, environment constraints and checks not run.
11. Apply quality gates; distinguish pass, fail, blocked and accepted risk.
12. Produce independent report with evidence and residual risk.

QA evaluates evidence, not developer claims. Completion is not a test pass. QA can reject or request fixes but cannot modify outside approved scope. Missing tooling is Not run with reason. Do not run destructive/production tests without explicit approval.
